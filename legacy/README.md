# Project Pulse — working starter
Install Node.js 22+, extract the ZIP, double-click start.bat on Windows or run `npm start`. Open http://127.0.0.1:7700. No npm dependencies. Keep server running for monitoring. Data is stored in data/state.json. Add absolute paths or discover immediate subfolders. Scans every 15 seconds; initial scan does not invent historical activity. Dates in heatmap use UTC. Firebase: install Google Cloud CLI, run `gcloud auth login`, ensure account has Hosting read access and API enabled. Enter Hosting site ID and optional remote path. Refresh retrieves site release and version file list; this integration requires live credentials and has not been tested against Firebase. Firebase hashes may be compressed, so remote equality is not asserted. Manual baseline requires you to independently confirm the current deployable directory matches production; a new release invalidates it. Timestamp status is only a hint, especially for shared sites. Source changes requiring rebuild may not affect the output baseline until rebuilt. No automatic deployment or file deletion. This starter uses polling and JSON rather than the proposed React/SQLite architecture. Native folder picker, Git, asset inspector, tasks, dependency graph, process launcher and full remote manifest verification are not implemented. Do not expose this local server to the internet. Back up data/state.json while stopped.
